# 言語学フェス2027：Microsoft FormsのExcelから行う3段階の抽選

このプログラムは、Microsoft Forms「言語学フェス2027 発表申込フォーム」の回答Excel（`.xlsx`。UTF-8の`.csv`も可）を**そのまま入力**として使います。フォームの設問は、2026年11月21日に共有された「言語学フェス2027 発表申込フォーム(4).pdf」に基づいています。**実際のForms Excel出力はまだ提供されていないため、最初の実データでは列名・タイムゾーンの確認を行ってください。**

## 1. 抽選日・締切・定員

| 項目 | 規則 |
|---|---|
| 発表申込締切 | **2027年2月1日（月）12:00（日本時間）** |
| 抽選に使う株価 | **同日2月1日（月）の日経平均株価の終値** |
| 本番判定 | 同日16:00 JST以降。終値が自動取得できない場合は停止 |
| 予行演習 | それ以前は直近の確定終値でPREVIEW。任意の架空終値で検証も可能 |
| A・B・Cのオンラインブース | 各36件、合計最大108件 |
| 3月28日現地ポスター | **各8件、合計最大24件**。ブース採択者の希望者から抽選 |
| 3月27日国語研の現地配信・参加 | **32席（主発表者1人あたり1席）**。居室あり・実行委員は定員外 |
| 現地配信の優先枠 | 現地ポスター採択者のうち、現地配信を希望した主発表者を優先 |
| 辞退による繰上げ | **いずれの抽選でも行わない** |

東京証券取引所の現物株式の取引時間は15:30までです。2月1日12:00に申込を締め切った後、同日終値が公開されます。公開数値が判明する前に、回答Excel・Rejectリスト・共著重複の手動指定リストを固定してください。株価自動取得元はYahoo Financeの`^N225`で、**本番公表前に日経公式公表値との照合が必要**です。

### SHA-256の計算式

全てUTF-8文字列のSHA-256を計算し、**16進64桁を昇順（小さい順）**に並べます。終値は`58123.45`のようにカンマなし・小数2桁、受付番号は4桁にゼロパディングします。

```
ブース       lingfes2027|A|58123.45|0001
現地ポスター lingfes2027|POSTER|A|58123.45|0001
現地配信     lingfes2027|ONSITE|58123.45|0001
```

`58123.45`は**架空の数値**です。ブースとポスターにはコアタイムA/B/Cを入れます。現地配信は「主発表者1人」を単位とし、同じ主発表者が異なる枠に複数の有効申込を持つ場合、その人の**最小の有効受付番号**で現地配信のハッシュ値を計算します。同じ人物が複数の抽選券を持たないための規則です。

## 2. Microsoft Formsからの入力方法

1. Microsoft Formsで対象フォームを開き、**「応答（回答） → Excelで開く」**から回答を保存します。
2. 保存した`.xlsx`を、Google Colabからアップロードするか、Mac/Windowsで`--input`に指定します。
3. **Excelの一行は、一回の送信**です。新規・申込修正・申込取消も同じExcelに含めます。
4. Formsが標準出力する最初の**`ID`列（回答ID）**を、A/B/C共通の受付番号とします。`1`→`0001`、`12`→`0012`、`123`→`0123`。取消回答・試験回答で番号が欠けても**再採番しません**。
5. **「完了時刻」列**で締切を検証します。Excel時刻にタイムゾーン情報がない場合は、設定`FORM_EXPORT_TIMEZONE`（初期値`Asia/Tokyo`）で解釈します。初回に実際の回答通知時刻と比較し、UTC記録なら`UTC`に変更してください。
6. `LAST_PRESENTER_ID=0`はExcelの最大回答IDを自動使用します。既知の最終IDを指定すると、Excelに最後の回答が欠けていないか一致検査します。

本プログラムは、フォームの質問タイトルのキーワードを照合して次の列を読みます。質問順・回答列順の変更は問題ありませんが、**質問の名前自体を変えた場合は読込対応が必要**になることがあります。

| Formsの設問 | 処理 |
|---|---|
| 主発表者の氏名／メールアドレス | 修正・取消の本人照合、現地配信の人物単位集約。非公開 |
| 手続きの種類 | 新規／申込修正／申込取消 |
| 以前の受付番号（申込修正・申込取消） | 旧回答IDへの照合。メール・氏名の一致が必須 |
| 発表するコアタイム | A/B/Cのいずれか。Excelの長い選択肢でも冒頭の枠名を認識 |
| 発表題目・発表概要・所属 | 内部台帳用。公開希望を得るまで公開しない |
| 共同発表者の氏名（所属）；区切り | `;`で分割し、所属括弧を除いて共著者照合 |
| 共同発表者同意・ポリシー確認 | 「はい」を確認（該当列がある場合） |
| 1日目 現地配信・参加（3択） | いいえ／32席抽選対象／居室あり・実行委員で定員外 |
| 2日目 現地ポスター（はい・いいえ） | ブース採択後の各枠8件の抽選対象 |
| フェス・ギャラリーの掲載希望 | 掲載希望を記録。**資料は同意なしで公開しない** |
| ブース抽選に漏れた場合のオンライン参加希望 | 参加案内の内部データとして保持 |
| 次回以降の運営参加希望 | 内部の希望者一覧CSVに出力 |
| 発表資料のアップロード | Excelに列がある場合は参照情報のみ保持。プログラムはファイル本体を公開しない |

**重要：**「すべてのユーザーが回答可能」のMicrosoft Formsでは、ファイルアップロード質問が利用できない制約があります。学外利用者のPDF提出は国語研が許可した別のアップロード方法で確認し、申込締切までの提出完了を別途照合してください。このプログラムは、Excel列のファイル名だけを根拠にPDF提出の有効性を判断しません。

## 3. 修正・取消・重複・Rejectの優先順位

1. **試験登録**（`TEST_REGISTRATION_REJECT_IDS`）は完全除外し、番号を公表しません。
2. **事務局による多重申込Reject**（`MULTIPLE_APPLICATION_REJECT_IDS`）はブース・ギャラリーの両方から除外し、番号を公開します。
3. **締切後**の回答は除外します。締切後の取消は過去の有効回答を取り消しません。
4. **申込修正**は新回答IDで受付。旧IDの主発表者の氏名・メールアドレスが一致し、旧IDが現役であるときだけ旧申込を「修正済み」にします。修正前の応募はギャラリー対象外です。
5. **申込取消**は同じ照合後に旧申込を取り消します。取消依頼自体はブース抽選対象外です。
6. **同一コアタイムの共著者重複**は、最後の有効申込だけブース抽選へ、以前の申込はギャラリー候補へ。**異なる枠間の重複は許可**します。
7. 事務局による手動ギャラリー指定（`COAUTHOR_GALLERY_MOVE_IDS`）も抽選から外します。
8. 残りの申込だけでブース抽選を行います。ブース非採択・共著者重複の資料公開は、ギャラリー掲載希望を回答した場合に限ります。

同姓同名・改姓・所属表記の違いは自動で確定できません。共著者の機械判定結果を本番前に人手で確認し、必要なら事務局の手動指定を使ってください。**本人確認を満たさない修正・取消は、勝手に処理せずエラー停止**します。既に修正済みの旧番号を指定する操作もエラーにします。

## 4. 3種類の抽選

- **ブース抽選：**各枠に属する有効申込を、上記ハッシュの昇順に並べた上位36件。37位以降はギャラリー候補。繰上げはありません。
- **現地ポスター抽選：**ブース採択者かつQ14の希望者のみで、各枠ハッシュ昇順の上位8件。現地ポスターの採択を理由にオンラインブースの順位は変更しません。
- **現地配信・参加：**フォームでQ13に「はい」と回答した**主発表者**を対象とし、同一人物のA/B/C応募を1人にまとめます。国語研内に居室がある方または実行委員は32席の定員外です。残る希望者のうち、現地ポスター採択者を先に割当て、32席の残りを`ONSITE`ハッシュの昇順で決めます。Q13が「いいえ」の方にはポスター採択による優先席も割り当てません。

**一般参加募集との関係：**このプログラムが現在抽選する32席は**この発表申込フォームに回答した主発表者**です。2月8日以降の一般参加申込者を同じ32席の母集団に含める場合は、別フォームのデータと締切後の公開数値が必要です。**2月1日の終値が既に知られた後で申込番号を配って同じ種で抽選するのは公平ではありません。**

## 5. Colabで実行

`lingfes2027_lottery.ipynb`をGoogle Colabで開き、上からセルを実行します。最初のセルが`yfinance`と`openpyxl`をインストールし、次のセルでPythonコードを生成します。設定セルで手動除外IDと最終IDを指定し、Formsからダウンロードした**回答Excelファイルを1個だけ**アップロードしてください。

## 6. Mac/Windowsで実行

```sh
python -m pip install -r lottery/requirements.txt
python lottery/lingfes2027_lottery.py --input "言語学フェス2027 発表申込フォーム.xlsx" --mode auto
```

終値がまだ判明していない段階の検証は、架空の終値を指定できます。

```sh
python lottery/lingfes2027_lottery.py --input "回答.xlsx" --mode preview --preview-close 58123.45
```

テストはネット接続なしで実行できます。

```sh
python -m unittest discover -s lottery/tests -v
```

## 7. 結果の保存と公開

実行結果は`lingfes2027_lottery_results/`に保存されます。

- **`internal_private/`：**全履歴、氏名・メール、ブース順位、ポスター順位、現地配信順位、試験登録、Reject、修正取消、運営参加希望、監査用条件など。**絶対にGitHubへ置かないこと。**
- **`web_public/`：**個人名を含まない`index.html`、ブース／ポスター／現地配信の匿名順位CSV、多重Reject番号、ギャラリー対象番号、抽選条件JSON。**本番と照合し、事務局が承認した場合だけ**公開。

結果を自動で`main/public/`へ混ぜないでください。既存の`mirror-new2.sh`と`publish_gate.py`を使う場合は、**事務局の本番承認後に限り、抽選専用ディレクトリへ同期**してください。実データや試験用ExcelをWebに置くことはありません。

## 8. GitHubのWindows Web画面から更新する場合

ZIP内の**同じパスにあるソースファイル**を`main`ブランチへ上書きします。`src/2027/index.html`と`src/index.html`は案内、`scripts/build_site.py`はポスター定員のバリデーション、`lottery/`以下は抽選プログラムです。`main`の更新後、GitHub Actionsが`public/`を生成します。`lottery`ブランチも保守するなら、同じ`lottery/`ソースを別途反映してください。`web_public/`は実行結果なので**今はGitHubへ登録しません**。
